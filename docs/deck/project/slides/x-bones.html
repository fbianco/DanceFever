A pose is a point on the 9-torus

p_k = (1 − x_k, (H/W)·y_k) mirror, square units

u = (p_j − p_i) / ‖p_j − p_i‖ ∈ S¹ bone i → j

u = (s·sin a, cos a), s = ∓1 left / right

pose = (u_1, …, u_9) ∈ (S¹)⁹ = T⁹

9 bones: both upper arms, forearms, thighs and shins, plus the torso (hip centre → shoulder centre). With the side sign s, a move and its mirror image have the same angles: 0° down, 90° out, 180° up.

Invariant under p ↦ λp + t (λ > 0): size and position do not matter. Not under rotation, on purpose: a tilted arm is another move.

A choreography is a path on T⁹. The coach moves each angle along the shorter arc, a(u) = a_i + Δ·(3u² − 2u³), arriving exactly on the beat.

From here on, the game’s own code. Each landmark is mirrored, x becomes 1 minus x, so the picture behaves like a mirror, and y is multiplied by the aspect ratio so that both axes use the same unit. A bone is then just the unit vector from one landmark to another: a point on the circle S1. The game uses nine bones, so a pose is a point on the product of nine circles, the 9-torus. Writing each limb as an angle measured from straight down, with a sign for the side, makes a move and its mirror image share the same numbers, which keeps the choreography files short. Because only directions are kept, the representation is invariant under translations and positive scalings of the body: a six-year-old and an adult doing the same move land on the same point. It is deliberately not rotation invariant. A dance is a path on the torus; the coach interpolates each angle along the shorter arc with a smoothstep easing, reaching each key pose exactly on its beat.
